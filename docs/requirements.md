# 小虫友记 — 需求分析

> 状态：v2（左页由「逸闻条目列表」改为「好友头像网格」）｜ 最后更新：2026-09-14
> 站点：小虫友记（提瓦特漫游记录）
> 形态：纯静态站点（HTML + CSS + 原生 JS，无构建工具）｜ 托管：GitHub Pages

---

## 1. 项目概述

一句话：**一个以「好友」为索引、展示原神（提瓦特）游戏截图的个人静态网站，浏览体验参考游戏内「游逸旅闻」界面的视觉语言与信息结构。**

| 项 | 内容 |
|---|---|
| 站点名称 | 小虫友记 |
| 副标题 | 提瓦特漫游记录 |
| 性质 | 个人站、非商用、非官方 |
| 内容 | 按好友组织的游戏截图（图片为主，配一句话备注） |
| 语言 | 简体中文 |
| 受众 | 站点主人自己 + 分享给同好/朋友 |
| 成本目标 | 0 元（全部使用平台免费额度） |

## 2. 目标与非目标

### 2.1 目标

- **G1** 以图片为绝对主角展示与各好友的游戏截图
- **G2** 浏览体验有沉浸感与游戏氛围（摊开的书 + 游逸旅闻式的选人方式）
- **G3** 持续更新的成本极低：新增一位好友 = 只改一处数据
- **G4** 零运维、零成本、可长期存活
- **G5** 手机端可用（浏览场景大概率发生在手机上）

### 2.2 非目标（明确不做）

- **N1** 用户系统、登录、评论、点赞
- **N2** 后端、数据库、服务端渲染
- **N3** 站内搜索与筛选（初期）
- **N4** 多语言
- **N5** 商业化、广告、付费内容
- **N6** 后台管理界面（内容通过直接编辑数据文件维护）

## 3. 用户与使用场景

| 角色 | 场景 | 关注点 |
|---|---|---|
| 记录者（站点主人） | 截图攒够一批后，新增一位好友或给已有好友补图 | 加内容够快、格式够简单 |
| 访客（同好/朋友） | 从链接进入，点好友头像看照片 | 图片清晰、加载快、手机上好看 |

典型路径：

1. 访客进入 → 看到一本摊开的书：左页是好友头像网格，右页默认显示第一位好友的图片
2. 点左页任一头像矩形 → 右页换成该好友的图片，书外背景随之虚化变化
3. 点右页大图 → 全屏放大，可用 ←/→ 翻看该好友的其他图
4. 想分享某个好友 → 复制带 `#/friend/<id>` 的链接

## 5. 内容模型

每位好友 = `assets/js/data.js` 里 `FRIENDS` 数组的一个对象。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识，用于 `#/friend/<id>`，不可重复 |
| `name` | string | ✅ | 好友名，显示在头像底部与右侧信息条 |
| `avatar` | string | | 头像路径；**可省略**，省略时自动取 `images` 的第一张 |
| `note` | string | | 一句话备注，显示在右侧信息条 |
| `tags` | string[] | | 标签（如地区、元素） |
| `images` | string[] | ✅ | 该好友的全部图片；第一张作为右侧大图默认显示 |

**规则**

- 排列顺序：按数组书写顺序（不做自动排序）
- 头像来源：`avatar` 优先，缺省取 `images[0]`
- 右页图片集合：`images`（为空时退回头像，保证右页不空白）
- 头像框为 `object-fit: cover`，**头像图本身应为正方形**，否则会被裁切

### 5.1 图片规范（已确认：图片放进仓库）

| 项 | 规定 |
|---|---|
| 头像位置 | `assets/img/avatars/` |
| 头像尺寸 | 正方形，建议 ≥ 400×400 |
| 配图位置 | `assets/img/records/` |
| 格式 | WebP（原图留在本地存档，不入库） |
| 配图尺寸 | 长边 ≤ 1920px |
| 体积 | 单张 ≤ 300KB |
| 命名 | 配图 `<好友id>-<序号>.webp`，例如 `friend-06-01.webp` |

容量估算：十几位好友 × 每位 3–5 张 × 300KB ≈ **10–20MB**，约占 GitHub Pages 1GB 上限的 2%。

## 6. 界面与交互形态

**布局**：居中一本摊开的书

- 左页 = 好友头像网格（每行多个矩形，点击选中）
- 右页 = 图片舞台（大图 + 缩略图条 + 信息条）
- 书外 = 当前图片的虚化背景

**右页照片墙（现行形态）**

- 照片为白框印相纸，错落摆放：每行两张，倾角 ±5° 内随手一放；同一好友的排布由稳定伪随机固定，刷新不跳动
- 照片左下角可挂一块白色小标牌写地名（`captions` 有值才显示）
- 整页可铺一张底图（`plate` 字段），并自动压一层浅色蒙版；不铺则用奶油底衬（淡彩纸屑 + 暖阳 + 气球）
- **右页图片区任何情况下都可上下滑动**（含照片不足一屏或无照片的条目）：用隐形前后垫片保证内容不足时垂直居中、且始终有约 150–300px 的滚动行程；无照片条目下滑时底衬纸屑有轻微视差作为反馈
- 照片超出可视高度时滚动行程更长；滑到尽头时顶部/底部各有一条渐隐"纸边"提示下面还有内容，到底自动消失
- 姓名页签固定在顶部，不随照片一起滚动

**视觉语言**：羊皮纸底 `#f7efdd`、金色 `#d4af37`、褐色文字 `#5c4d42`、衬线标题、金色细描边、菱形装饰。

**三种状态**

| 状态 | 宽屏 | 窄屏（≤1040px） |
|---|---|---|
| 头像网格态 | 左页常驻可见 | 整屏显示头像网格 |
| 图片态 | 右页常驻可见 | 图片页从右侧滑入覆盖头像页 |
| 放大态 | 全屏遮罩，覆盖一切 | 同左 |

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 不加载 Web Font；图片按需加载；CSS + JS 合计 < 25KB（当前约 24KB） |
| 兼容 | 现代浏览器近两年版本（Chrome / Edge / Safari / Firefox）；移动端可用 |
| 本地预览 | 无需构建；双击 `index.html` 即可预览（数据用 JS 数组而非 `fetch`，规避 `file://` 的 CORS） |
| 可维护 | 新增一位好友只改 `data.js`，不触碰 HTML/CSS |
| 可访问性 | 头像矩形为 `button` 可键盘访问；图片有 `alt`；有焦点样式；支持 `prefers-reduced-motion` |
| SEO | 基础 meta + og 卡片；内容位于 JS 数据中，不被搜索引擎收录（已知取舍，个人站可接受） |
| 部署 | GitHub Pages，分支直发（Deploy from a branch），无 CI |

## 8. 约束与风险

### 8.1 约束

| 约束 | 说明 | 应对 |
|---|---|---|
| 版权 | 原神为米哈游 IP；不得使用官方美术素材（角色立绘、logo、UI 贴图） | 页脚已按站主意愿改为个人化文案（"我是小虫，这是我的朋友们^_^"），免责声明如仍需保留，宜放到 README 或关于页；装饰元素须自绘（当前菱形角标为自绘） |
| 托管配额 | GitHub Pages：站点 ≤ 1GB、带宽 100GB/月（软限） | 图片必须压缩；不宜把大量原图放进仓库 |
| 大陆可达性 | `github.io` 无大陆节点，存在 DNS 污染与 SNI 阻断，可达性因地区/时段而异 | 不以"所有大陆访客都能打开"为前提；必要时再考虑自定义域名 |
| 技术约束 | 纯静态、无构建 | 无法用 Markdown 写内容，备注以 JS 字符串维护 |
| 单点存储 | 内容与代码同仓库 | 仓库损坏即内容丢失；建议保留本地备份 |

### 8.2 风险（按严重度）

- **R1【低 — 已有控制策略】图片体积** — 游戏原图动辄数 MB，但已确认规模为十几位好友且图片压缩后入库：按每张 ≤ 300KB、每位 4 张估算，总量约 10–20MB，距离 1GB 上限仍有充足余量。
  *控制策略*：入库前统一转 WebP、长边 ≤ 1920px、单张 ≤ 300KB（见 §5.1）。
- **R2【低】文字写在 JS 字符串里** — 换行、引号、特殊字符容易出错，内容变多后维护体验下降。
  *判断*：已确认每位好友只有一句备注，纯 JS 字符串维护无压力。
- **R3【中】依赖 JS 渲染** — 禁用 JS 时页面空白。个人站可接受。
- **R4【低】hash 路由的 SEO** — 好友页不被搜索引擎索引。可接受。

## 11. 决策记录与待确认问题

### 11.1 已确认的决策

| 编号 | 问题 | 结论 |
|---|---|---|
| Q1 | 图片怎么存 | **放进仓库**，入库前按 §5.1 压缩（十几位好友规模下容量充裕） |
| Q2 | 每位好友的文字量 | **一句话**，不需要折叠 → F9 降级为可选 |
| Q3 | 数量级 | **十几位以内** → 维持纯 HTML + `data.js`，不引入静态生成器 |
| Q6 | 左页形态 | 由「逸闻条目列表」改为**「好友头像矩形网格」**，点击矩形在右侧看该好友的图片（v2 变更） |
| Q8 | 右页照片多到放不下怎么办 | **右页图片区可上下滑动**，超出部分滚动查看；顶部/底部用渐隐纸边提示（宽屏与窄屏行为一致） |
| Q9 | 无照片（空白）条目右页还能滑吗 | **能滑**：垫片机制保证任何条目都有统一滚动行程，下滑时纸屑视差提供视觉反馈（v2.1） |

### 11.2 待确认

| 编号 | 问题 | 影响 |
|---|---|---|
| Q4 | **是否需要按标签 / 地区筛选好友**？ | 决定是否做 F14 |
| Q5 | **文案是否始终纯中文**？出现英文/日文术语时的排版处理 | 影响字体栈与中英混排细节 |
| Q7 | **左页每行排几个矩形、矩形用什么比例**（当前 84px 列宽下限、1:1 正方形） | 需在浏览器看过实际效果后定 |
