# 小虫友记 — 需求分析

> 版本：v3  
> 更新时间：2026-09-21  
> 依据：当前 `index.html`、`assets/js/data.js`、`assets/js/main.js` 和 `assets/css/style.css`  
> 站点类型：纯静态个人相册，无构建工具、无后端

## 1. 产品定位

小虫友记是一个以好友为索引的游戏截图与视频相册。访客先选择好友，再浏览该好友的照片墙和视频；桌面端使用展开书本的视觉形式，移动端使用单页滑入的浏览形式。

网站的核心价值是让图片成为主角，同时保留个人记录、朋友索引和可分享的好友页面。

## 2. 用户与使用场景

### 2.1 访客

- 从首页浏览好友头像。
- 点击好友查看对应照片和视频。
- 点击图片进入全屏查看，使用键盘或手势翻页、缩放。
- 通过 `#/friend/<id>` 分享某位好友的页面。

### 2.2 站点维护者

- 新增一位好友。
- 为已有好友补充图片或视频。
- 修改头像、底图、图片标题和素材尺寸。
- 不需要数据库、后台或构建流程。

## 3. 当前页面结构

### 3.1 首页

- 左页显示站点标题、站主“小虫”和好友头像网格。
- 好友头像使用按钮元素，可鼠标点击、键盘聚焦。
- 当前好友使用金色光晕表示选中。
- 桌面端首页默认只显示左页，右页在选择好友后展开。
- 移动端首页只显示好友列表，右页以滑入层显示。

### 3.2 照片页

- 右页使用好友专属底图，或默认底图。
- 图片以照片墙形式排列，桌面端通常为双列，手机端为单列大图。
- 图片使用缩略图优先加载，缩略图缺失时回退原图。
- 视频直接在照片墙中播放，支持控件、循环、静音和移动端播放。
- 照片墙右侧使用固定拉绳作为共同相册控制器，不再显示进入卡片或返回按钮。点击拉绳后幕布以约 320ms 的线性位移从顶部拉下并遮住内容，切换完成后再以约 320ms 的线性位移向顶部收回；不模拟横向摆动、回弹、旋转、淡入淡出或阴影变化。共同相册使用独立底图、排版和无顶部文案。再次点击同一根拉绳时按相同方式返回个人照片。站主个人照片页不显示共同相册控制器。
- 照片页始终保留可滚动空间，即使好友没有图片。

### 3.3 全屏查看层

- 图片点击后进入全屏放大层。
- 支持上一张、下一张、键盘左右方向键、手机左右滑动。
- 支持滚轮、双击和双指缩放，放大后可拖动图片。
- 支持 Esc 和点击遮罩关闭。
- 视频目前不进入全屏查看层，只在照片墙中播放。

## 4. 功能需求

### P0：必须保持

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F1 | 好友头像网格 | 首页显示全部好友，头像顺序与 `FRIENDS` 数组一致 |
| F2 | 好友切换 | 点击好友后照片页内容、底图和选中状态同步变化 |
| F3 | 桌面端展开 | 宽屏点击好友后书本展开，显示左页和右页 |
| F4 | 移动端切换 | 窄屏点击好友后照片页滑入，返回按钮回到好友列表 |
| F5 | 图片照片墙 | 多张图片能滚动浏览，图片不因固定画幅被明显裁切 |
| F6 | 视频播放 | 视频有 poster、控件、循环、静音和 `playsinline` |
| F7 | 图片放大 | 点击图片进入全屏层，可翻页、缩放、拖动和关闭 |
| F8 | Hash 路由 | `#/friend/<id>` 可直接打开对应好友，浏览器前进后退可同步状态 |
| F9 | 空相册回退 | 没有图片时使用头像或占位文案，页面不能显示为加载失败状态 |
| F10 | 内容易维护 | 新增好友只需修改 `data.js` 并添加素材，不修改页面结构 |
| F11 | 基础可访问性 | 头像和照片可聚焦，有替代文本和可见焦点样式 |
| F12 | 静态部署 | 可直接通过 GitHub Pages 或本地静态服务器部署 |
| F13 | 共同相册状态切换 | 右页固定拉绳可用键盘和触摸操作；点击后幕布先以约 320ms 的线性位移从顶部拉下并遮住内容，切换完成后再以约 320ms 的线性位移向顶部收回；共同相册不显示顶部文案；再次点击同一根拉绳可返回个人照片，站主个人页不显示该控制器 |

### P1：建议补齐

| 编号 | 需求 | 原因 |
|---|---|---|
| F14 | 放大层显示 `当前序号 / 总数` | 让访客知道浏览进度 |
| F15 | 修正统计文案 | 当前“已收录 N 则记录”实际统计的是好友数量，应改为“已收录 N 位好友” |
| F16 | 处理无效 Hash | 无效好友 ID 应清理地址或显示明确的不存在状态，不能只静默回退到第一位好友 |
| F17 | 完善全屏层语义 | 增加 `role="dialog"`、`aria-modal`、焦点进入和焦点返回 |
| F18 | 统一站点元信息 | 页面标题、描述、OG 标题和站内品牌统一使用“小虫友记” |
| F19 | 明确视频放大策略 | 决定视频是否需要单独的全屏播放入口 |
| F20 | 数据字段约束 | 新增字段必须有页面用途，避免再次积累死数据 |

### P2：暂不纳入

- 标签、地区或元素筛选。
- 好友自定义排序。
- 登录、评论、点赞和后台管理。
- 数据库、服务端渲染和构建系统。
- 多语言。
- 访问统计。

## 5. 数据模型

好友数据位于 [assets/js/data.js](../assets/js/data.js) 的 `FRIENDS` 数组中。

| 字段 | 类型 | 必填 | 当前用途 |
|---|---|---:|---|
| `id` | string | 是 | 好友唯一标识和 Hash 路由 |
| `name` | string | 是 | 头像替代文本、按钮标题、照片标题 |
| `avatar` | string | 否 | 好友头像；缺省时从图片中回退 |
| `badge` | string | 否 | 头像上方的装饰图片 |
| `plate` | string | 否 | 照片页底图 |
| `images` | string[] | 是 | 图片和视频列表 |
| `dims` | object | 否 | 预设媒体宽高，减少布局跳动 |
| `captions` | string[] | 否 | 图片标题和放大层说明 |
| `masonry` | boolean | 否 | 是否使用桌面端双列瀑布布局 |
| `together` | object | 否 | 与站主一起拍摄的共同相册 |

`together` 可包含 `images`、`captions`、`dims`、`plate` 和 `masonry`。没有配置时拉绳仍然显示，打开后给出空相册提示；站主个人页不显示该控制器。

备注和标签暂不属于当前数据模型；如果未来需要展示，再新增对应字段和界面需求。

站主“小虫”使用独立的 `ME` 对象，位于品牌区右上角，同时拥有自己的图片页。

## 6. 素材规范

当前代码实际使用以下目录：

- 头像：`assets/img/avatars/`
- 相册原图和视频：`assets/img/album/`
- 相册缩略图：`assets/img/album/thumb/`
- 照片页底图：`assets/img/plate/`
- 页面装饰：`assets/img/`

新增素材应满足：

- 头像尽量使用正方形图片。
- 图片提供对应缩略图时优先放入 `album/thumb/`。
- 视频提供同名 `-poster.jpg` 海报图。
- 在 `dims` 中写入已知宽高，降低首次布局变化。
- 大图控制尺寸和体积，避免 GitHub Pages 首屏加载过重。

## 7. 非功能需求

### 性能

- 图片墙使用懒加载。
- 放大层只加载当前原图，并预取相邻图片。
- 视频使用 `preload="metadata"`。
- 不引入 Web Font、前端框架或运行时依赖。
- 当前 CSS、主脚本和数据脚本合计约 65 KB；旧文档中的 25 KB 目标已不符合现状，应以可感知加载速度为准。

### 兼容性

- 支持近两年的 Chrome、Edge、Safari 和 Firefox。
- 支持手机竖屏浏览。
- 支持 `prefers-reduced-motion`。
- 支持无 JavaScript 以外的静态资源直接访问。

### 部署

- 使用 GitHub Pages 分支直发。
- 保留 `.nojekyll`。
- 不需要 CI、打包或服务器。

## 8. 当前实现与旧文档的差异

旧版本需求描述中，以下内容已经失效：

1. 当前不是“右页主图加缩略图条”，而是“照片墙加全屏放大层”。
2. 当前没有显示“第几张 / 总数”。
3. 当前选中态是金色光晕，不是菱形角标。
4. 当前照片墙使用规整布局，照片旋转参数固定为 0 度。
5. 当前素材路径是 `album/`，格式主要是 JPG 和 MP4，不是 `records/` 下的 WebP。
6. 当前桌面端首页不会自动显示右页，必须点击好友后展开。
7. 备注和标签暂不属于当前数据模型。

后续设计、开发和验收应以当前代码行为为基线。
